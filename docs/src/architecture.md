# 架构

> 本页是 `pdr.md`（v3.2）§12「架构」的摘要。权威源以 `pdr.md` 为准。

## 架构层次（§12.1）

自上而下四层：

```
┌─────────────────────────────────────────────────────┐
│ 业务蓝图（Action AST）                              │ ← 开发者编写
├─────────────────────────────────────────────────────┤
│ 运行时模型（Cordis 理论）                           │ ← 管理逆操作、依赖通知、时间重放
│   - trackΓ / recoverΓ（撤销栈）                     │
│   - notify（组件激活/停用，可选）                   │
│   - VirtualClock（逻辑时间，可选）                  │
├─────────────────────────────────────────────────────┤
│ Rust 编译期安全层（所有权、生命周期、借用检查）      │ ← 编译器保证内存安全
│   - 资源线性由 move + Drop 保证                     │
│   - 内存安全由借用检查器保证                        │
├─────────────────────────────────────────────────────┤
│ 物理执行层（tokio）                                 │ ← 系统调用
└─────────────────────────────────────────────────────┘
```

## 物理后端（§12.2）

Algeff 默认使用 **tokio** 作为跨平台异步运行时，不直接依赖 mio 或 io_uring。tokio 已封装 epoll/kqueue/IOCP，并支持异步文件、网络、信号、定时器。

| 平台 | 网络后端 | 文件后端 |
| --- | --- | --- |
| Linux / macOS / Windows | `tokio::net`（基于 mio） | `tokio::fs`（线程池） |

如需更高性能的文件 IO，可启用 io_uring feature（仅 Linux），但会增加构建复杂度，**默认不启用**。

## 运行时核心结构（§12.3）

`Runtime` 的核心字段：

- `context`：当前上下文（含状态和累积逆变换）
- `undo_stack`：撤销栈（逆操作闭包）
- `dependency_table`：依赖表（余效应上下文，可选 feature）
- `loaded_components`：已加载组件列表（可选）
- `virtual_clock`：逻辑时钟（可选 feature）
- `resource_registry`：资源注册表（全局标识分配与冲突检测）
- `reactor`：tokio 异步运行时（`Runtime::new` 须在 tokio 上下文外调用，见契约 D9）

设计要点：**没有泛型参数、生命周期标记或常量泛型**——所有复杂度由运行时内部管理。Rust 实现对应 `crates/algeff-core/src/runtime.rs`（A2 拥有）。
