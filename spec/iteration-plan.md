# 20 轮迭代规划（生产就绪路线图）

> 状态：2026-08-16 起。目标：生产就绪（语义闭环 + DX 哲学改进 + 性能达标 + 真实发布）。
> 每轮 = 开发 → 审计/验证 → 合并闭环；对抗审计 × 形式逻辑审计持续贯穿。
> 基线：main `ca50728`（352 测试 / 49 块绿，D-001~D-078）。

## 阶段划分

| 阶段 | 轮次 | 主题 | 产出 | 验收 |
| --- | --- | --- | --- | --- |
| **A. 缺陷闭合** | 1-4 | RFC-05/06/07/08/09/12 残余全修 + R-6 锁重构 | 6 项修复 + 性能对照数据 | 反转断言全绿；parallel_reads 366%→~100-150% |
| **B. DX 哲学** | 1-7 | 最小例子去吓人化（do! 宏/操作对象/资源自动推导） | dx-design 文档 + 新语法 + README 重写 | 最小文件 IO 示例 ≤15 行、接近普通 Rust |
| **C. 验证** | 4-5, 10, 18-19 | 对抗审计 R7/R8 + 形式逻辑终审 | 新对抗套件 + P4 收敛判定 | RFC-05 闭合后 P4 升级评估；义务表 R7/R8 行 |
| **D. 发布** | 8-13 | 性能二轮优化 + 发布演练 + 真实 publish | release-checklist + 三 crate 发布 | crates.io 可见、cargo add 自测通过 |
| **E. 深化** | 14-17 | 反应性/coeffects 深化 + 教程体系 | 新能力 + getting-started 教程 | 教程基于新 DX 语法完整可跑 |

## 并行策略

- 每轮 ≤8 路并行（worktree + 分支），CTO 独裁合并（门禁：cargo test + fmt + clippy + 冲突标记 grep + 文档一致性脚本）
- 对抗/形式审计独立不阻塞开发（既有纪律）
- Watchdog 心跳持续
