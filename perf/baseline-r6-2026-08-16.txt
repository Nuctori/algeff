[1] echo 臂（algeff_echo：tokio_native_100conns_x1rtt_1KB vs algeff_100conns_x1rtt_1KB）
--------------------------------------------------------------------------------
场景:   本地 TCP echo（127.0.0.1），每测量样本 100 连接 × 每连接 1 次 1KB 往返
        （A4 线性语义下 CTO 裁决的等负载双对比项；pdr.md §16「网络 Echo」）
参数:   sample_size=10, warm_up=50ms, measurement_time=100ms（每样本 ~1 iter）
复测 3 次（criterion 各次点估计/原始样本中位数，单位 ms）：

  运行      原生(tokio_native)     Algeff          对比 = Algeff/原生
  1         28.514                 28.610           100.3%
  2         29.896                 28.659            95.9%
  3         28.680                 29.130           101.6%
  3 次中位数  28.680                28.659            99.9%

对照基线（2026-08-15）:
  原生: 27.771 ms → 28.680 ms（+3.3%）
  Algeff: 28.624 ms → 28.659 ms（+0.1%）
  对比: 103.1% → 99.9%（-3.2 个百分点，处于基线自记的每样本 1 iter ±10% 噪声带内）

结论: echo 顺序路径无回归（RFC-10/JD 错误映射仅错误路径，成功路径无开销佐证）。

[2] append 臂（algeff_append：tokio_native_10tasks_x32KB vs algeff_serial_10tasks_x32KB）
--------------------------------------------------------------------------------
场景:   10 任务追加同一文件（每任务 32 × 1KB = 320KB/样本；D6 默认串行路径
        Algeff 臂：10 任务顺序 Open{append}+Write(32KB)+Close）
参数:   sample_size=10, measurement_time=3s, setup 不计时
复测 3 次（criterion 点估计，单位 ms）：

  运行      原生(tokio_native)     Algeff(serial)    对比 = Algeff/原生
  1         6.2816                 2.3618             37.6%
  2         6.0356                 2.4497             40.6%
  3         5.6275                 2.2636             40.2%
  3 次中位数  6.0356                2.3618             39.1%

对照基线（2026-08-15）:
  原生: 6.0947 ms → 6.0356 ms（-1.0%，无变化）
  Algeff: 1.4814 ms → 2.3618 ms（+59.4%，显著变慢）
  对比: 24.3% → 39.1%（+14.8 个百分点，超 5% 阈值）

结论: append 顺序路径 Algeff 臂显著回归（见文末 Findings #1）。

--------------------------------------------------------------------------------
Findings（对照阈值：对比百分比变化 >5% 记性能回归；README 表偏差 >10% 记文档漂移）
--------------------------------------------------------------------------------
#1 性能回归（append 顺序路径 Algeff 臂）：
   对比百分比 24.3% → 39.1%（+14.8 个百分点 > 5%）；Algeff 中位 1.4814 →
   2.3618 ms（+59.4%），3 次复测一致（2.2636–2.4497），CI 与基线 CI
   （1.4344–1.5455）完全不重叠，非噪声。
   归因: af27ce9（R1 对抗审计写可见性修复，2026-08-15 21:05，晚于基线测量）
   在 op_write 全部成功分支无条件追加 file.flush().await —— 每次 Write 等待
   OS 落盘完成。基线时 Algeff 臂不 flush（基线文件明记「原生臂含每任务 flush，
   Algeff 臂不 flush（小量不对称）」），快于现行为正常契约成本：A4/A6
   「Write 完成 ⇔ OS 已落盘」可观察性契约（基线 24.3% 部分受益于未落盘即返回）。
   佐证: RFC-10 错误映射（e422462/609c393）仅错误路径，echo 臂成功路径无变化
   （+0.1%）；flush 为唯一命中 append 热路径的变更。
   处置建议（超出本审计范围，交审查/CTO 裁决）：接受为正确性契约成本并刷新
   文档（24.3% → 39.1%）；或优化（如 flush 仅当调用方可观察性需要时执行 /
   批量 flush），属 A5/执行器域，src/ 冻结不可由本审计改动。

#2 文档漂移（append 对比百分比）：
   性能表 append 对比 24.3%（README.md §性能、benches/README.md §4.4、
   docs/src/derivation.md、spec/g4-closure.md）与复测 39.1% 偏差 +60.9%
   （>10%）。属 #1 代码变更的直接后果（非数字抄错），待 #1 处置后一并刷新。

#3 文档漂移（边缘，原生 only append 表数字）：
   benches/README.md §1 表中位时间 append 7.1652 ms vs 复测 6.2319 ms
   （-13.0%，超 10% 阈值）。原生路径无代码变更，且基线自身两会话间即 ±15%
   抖动（[4] 7.1652 vs [8] 6.0947），判为会话间 IO 抖动而非真实漂移；按任务
   阈值如实记录，供审查裁决是否刷新表数字。

无回归确认: echo 对比 103.1% → 99.9%（-3.2 pts，噪声带内）；append 原生臂
            6.0947 → 6.0356 ms（-1.0%）。
